# 从用户问题到交付

这是产品设计假设与本地实现案例，不是用户研究结论或线上业绩。目标是让评审者可以沿着用户任务、设计取舍、源码和验证记录追问。

## 用户为什么需要它

目标用户：需要整理大量口播片段的剪辑者。触发时刻：粗剪前反复听素材、挑片段、调节节奏消耗时间。

用户真正要完成的事：得到可以逐项复核、保留原始素材的初剪时间线。价值发生在这个任务完成时，不发生在模型输出字数增加时。

现有替代：手工标记可控但耗时，一键成片隐藏了语义断裂与剪切风险。差异化假设应通过真实任务对照验证，不能用功能数量或模型名称代替。

## 用户会怎么使用

提供素材索引 → 应用剪辑规则 → 生成时间线 → 逐段复核 → 修改节奏 → 人工确认后渲染。

首次使用以示例降低输入成本，再让用户带着自己的合规资料使用。每个处理中状态必须对应真实请求；失败保留输入，结果可复查、可导出。成功不是点击生成，而是用户能做下一步决定。

## 产品定义与技术分工

faster-whisper 提供本地转写、词时间戳和识别信号；脚本提供时间、预算与素材边界约束；用户在审核台判断语义、顺序与切点。当前不自动分析片段角色和审美。

关键取舍：先交时间线再渲染；非法时间段排除；用户要求更紧凑必须同步单片上限。最重要的失败模式：文字转录无法识别所有画面与语气信息；脚本生成并不代表剪辑质量获认可。

界面入口：[web/index.html](../web/index.html)，使用 review_server.py 打开。实现入口：[scripts/stage2_generate_timeline.py](../scripts/stage2_generate_timeline.py)。

## 指标定义

| 指标 | 定义 | 采集方式 |
|---|---|---|
| 任务价值 | 编辑者接受的时间线片段占比；分母为建议时间线中的片段数 | 自愿参与的任务测试与人工标注 |
| 使用效率 | 从开始有效输入到完成核心动作的中位时长 | 本地计时，不收集原始问题正文 |
| 质量护栏 | 越界剪切数、语义断裂率、原始素材改动数、复核遗漏率 | 固定回归集和人工抽查 |
| 可用性 | 请求成功率、P95处理延迟、输入恢复成功率 | 去标识事件与运行日志 |

当前没有线上用户基线，不报告增长率或客户收益。先采集基线，再预注册改善目标，避免看完数据再选成功指标。事件字段契约见 metrics.schema.json；它是接入设计，不代表已有生产遥测。

## 价值验证计划

用虚构素材索引比较手工粗剪与规则辅助，记录片段保留率、调整次数、复核时间；不拿不存在的视频声称成片效果。建议首轮覆盖 5 名目标用户用于发现可用性问题，不以该样本估计市场效果。记录任务前提、失败位置和原话；未执行前均为计划。

技术回归与用户验收分开：Schema通过只能证明结构；构建通过只能证明可构建；虚构检索集通过只能证明小样本链路；真实任务成功才支持用户价值。

## 迭代顺序

1. 当前版本：建立明确输入/输出、失败恢复、示例、测试和可审阅文档。
2. 0.3 已接入本地 ASR 和浏览器审核，使用自行生成的媒体做技术验收。下一阶段需真实授权素材逐段标注，测量试听纠错成本，再决定是否增加语义推荐。
3. 扩展条件：只有核心任务通过且护栏没有恶化，再扩展自动化、数据源或模型。

## 面试时可以展示

先用一个具体任务展示入口与失败状态，再打开设计取舍和测试，解释为什么某些步骤用规则、另一些步骤需要模型。展示本地证据，同时明确线上部署、客户收益和专业有效性未获验证。

外部组件解决通用技术问题；本项目的可归属贡献是问题定义、流程设计、约束、接口集成和验证，不把开源模型能力说成自研算法。

## 0.4：剪完以后继续工作

口播初剪交给精剪时，剪辑者还需要与新顺序对应的文字。复用原始字幕会错位，重新识别则增加等待并丢掉先前识别记录的可追溯性。已有词时间戳可以直接映射到审核后的切片，作为下一步字幕校对的起点。

因此先提供独立 SRT/VTT 和源时间映射，保留字幕可编辑性。暂不默认烧录：一旦识别错字被固化到画面，用户需要重新导出视频。对缺失或切断的词明确留下缺口，宁可要求回听，也不推测没有完整发音支持的文字。每个切片使用实测渲染时长累计偏移，避免帧率与音频封装带来的累计偏差。

验证指标是字幕映射越界数、剪辑重排后时间一致性、源文件变化拦截率，以及后续真实用户研究中的校对耗时和漏字率。当前仅有合成媒体技术证据；没有节省时间或字幕满意度结论。
