# 面试演示提纲

用一个任务说明：剪辑者想先得到可控初剪，反复听素材和标记时间是高频成本。产品假设来自任务分析，尚无真实访谈结论。

1. 打开审核台，体验虚构索引的选择、顺序、切点、撤销和导出。
2. 展示原始 TTS 测试素材的转写报告：faster-whisper、词时间戳、识别信号、源文件哈希。不把 ASR 信号叫作音质或语义质量。
3. 展示浏览器实际播放、修改后 CSV 和 FFmpeg 输出；明确这些是技术测试素材。
4. 解释取舍：默认原顺序、完整片段、显式排除理由、用户可恢复，而非无根据的自动叙事排名。
5. 展示真实混合分辨率/帧率与无音轨拼接测试、键盘和手机回归。
6. 用 docs/product-case.md 的指标方案讨论如何招募真实剪辑者，对比手工标记时长与辅助工具纠错成本。

当前证据以 docs/validation.md 和 docs/acceptance-03.json 为准。旧文档曾写过 12 个视频、43 行、179 秒，但本轮没有可核查原始证据，不再作为已验证结果。没有客户效率、满意度或业务收益数字。Whisper 和 FFmpeg 为开源能力，本项目贡献是工作流、边界、审核体验与集成验证。
