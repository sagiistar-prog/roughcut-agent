# 为什么先做可审核初剪

用户需要的是节省重复听录音、标时间的劳动，同时保留对表达的判断。完全自动的剪辑可能把长句截断、重复同一段声音，或根据不可靠评分打乱叙事。重新修正的成本会抵消自动化收益。

0.3 从这三个风险出发调整方案：转写仅承担听写和时间信号；默认保留原顺序和完整片段；人可以试听、改变保留状态、移动、改切点和撤销。未选片段仍然可恢复，模型没有测量的项目明确未知。

数据路径为源文件哈希、ASR JSON/CSV、初选 JSON、审核会话、确认 CSV、FFmpeg 中间片段和最终报告。每个边界可独立复现。渲染统一视频和音轨参数，避免混合素材拼接依赖偶然相容。

产品价值仍是假设。已运行的合成媒体、真实浏览器和 FFmpeg 技术结果见 [验收](validation.md)，未冒充真实用户效果。下一步先收集授权口播素材与人工逐段标注，再比较首稿时间、纠错时间和断句率；在基本任务获益后考虑语义推荐或 EDL 导出。

完整用户任务、指标、取舍和验证计划见 [产品案例](product-case.md)。当前命令见 [README](../README.md)。
